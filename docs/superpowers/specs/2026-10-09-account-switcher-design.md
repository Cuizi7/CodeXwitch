# CodeXwitch — 简化菜单栏程序设计

日期：2026-10-09（Asia/Shanghai）

## 目标与范围

一个常驻 macOS 菜单栏程序，显示 Codex 的运行状态、当前认证账号和备选账号。点击备选账号后退出当前 Codex、替换 auth.json、重新启动同一份 App。A/B 顺序运行，共用原有配置、项目、会话和数据库。

Codex 可以独立从 Dock、Finder 或终端启动。小程序启动时必须识别已有 Codex 和当前账号，不依赖自己的启动记录。

独立 Swift/AppKit 程序，交付菜单栏 .app、源码、说明和测试记录。不增加 CLI 登录流程、第二份 Codex、第二个 CODEX_HOME、另一份桌面数据或登录专用目录。第一版支持本机原安装 App 和默认 ~/.codex 的文件认证。

## 菜单

    Codex：运行中
    当前：a@example.com
    ─────────────────────
    切换到 b@example.com
    ─────────────────────
    添加账号…
    刷新状态
    设置…
    退出菜单栏程序

没有“保存账号”按钮。当前账号不重复列入备选；没有账号时显示“未登录”。切换或准备登录时暂时禁用重复操作。退出小程序不会退出 Codex；不自动安装开机启动项。

## 设置与删除账号

“设置…”打开一个简单的原生窗口，列出已保存账号，标记当前使用的账号，每行提供“删除”按钮。点击删除后用系统确认框确认，仅删除小程序保存的该账号凭据，不改写活动 auth.json，不退出 Codex，不删除会话或项目。

允许删除当前账号的保存记录；菜单仍显示当前登录状态，但它不再作为可切换的已保存账号。为避免下一次自动检查马上保存回来，记住被移除的当前身份，在它持续作为当前账号期间跳过自动保存，包括凭据刷新。当前身份变为其他账号后解除跳过；用户主动走“添加账号”登录流程也解除跳过，允许重新保存。这一条排除记录随小程序重启保留。删除非当前账号不需要排除记录，下次实际登录它时自动保存。

窗口不增加路径、同步、额度等其他设置项。删除确认文字：“删除已保存的账号？这不会退出当前 Codex。若要再次切换到此账号，需要重新登录。”

## 自动识别与保存

小程序启动、打开菜单、收到 App 启动/退出事件时刷新，并每隔约两秒检查 auth.json 的变化。读到完整的 ChatGPT 登录凭据后，自动加入账号列表或更新已有账号的凭据，包括 OAuth 刷新后的版本。小程序未运行时登录的账号，也在下次启动时自动保存。

运行状态来自系统 App 列表；账号信息来自共享 auth.json 中的身份字段。用用户身份与 account/workspace 身份区分记录，email 用于显示。凭据暂时不存在或文件正在写入时，等下次检查，不删除已保存账号、不覆盖有效快照。

只在内存中解析身份与 token。自动保存到程序私有账号目录，目录权限 0700、凭据文件权限 0600；不记录 token，不上传凭据。保存成功后才标记为已获取该版本。

账号显示反映磁盘认证。正常外部启动、登录和重启均应正确工作；第一版不尝试连接 App 私有接口来核对内存缓存，也不处理外部工具在 App 运行时强行替换认证的竞态。

## 切换账号

1. 检查目标凭据可读，暂时暂停自动采集并禁用切换按钮。
2. 请求 Codex 正常退出并等待；未能退出则报错，不替换 auth.json。
3. 再读取并保存当前账号的最新凭据；保存失败则停止。若当前账号已被用户删除并处于跳过自动保存状态，则尊重删除选择，不重新保存。
4. 将目标凭据写入原 auth.json，再启动原 Codex。
5. 恢复刷新与自动保存，菜单反映状态。

已处于目标账号时不回放旧快照，只显示或启动 Codex。凭据使用系统提供的原子文件写入，避免半份 JSON；不引入事务日志、崩溃恢复状态机、数据库或跨客户端锁。

第一版只管理桌面 App 的退出和启动，不自动退出 VS Code、独立 CLI 或扫描其文件占用。它们共用认证时需由用户自行退出；程序不保证其他客户端同步切换。

## 添加账号

1. 请求现有 Codex 正常退出并等待。
2. 自动保存当前账号的最新凭据；保存失败则停止。已被用户明确删除的当前账号不重新保存。
3. 移除共享目录中的 auth.json，保留私有账号快照，不调用 codex logout。
4. 解除被移除当前身份的自动保存排除记录，启动原 Codex，使其进入未登录状态，用户直接在官方 App 中登录。
5. 小程序检测到新登录的 auth.json 后自动保存，并显示新账号。

没有临时登录目录，不用内置 CLI 代替 App 登录。选择同一账号登录只更新原记录。用户取消或放弃登录时，App 保持未登录；原账号仍在备选列表，点击即可切回。不会自动退出正在登录的 App 或猜测取消状态。

## 最小失败处理

操作失败时显示失败步骤并恢复菜单操作能力。已保存的账号快照保留；启动失败时用户可重试，或选择原账号重新启动。不自动回滚、不记录事务阶段、不处理复杂一致性问题。

只改写共享 auth.json 和程序自身的账号目录。认证后端并非文件、凭据无法解析或读写权限不足时明确报错，不修改原配置。保留正常退出确认、保存成功后再移除当前凭据、文件权限保护，避免最直接的凭据丢失；用户已明确删除当前账号保存记录时，尊重其不再保存的选择。

## 验收

```gherkin
Scenario: 接管外部启动的 Codex 并自动保存
  Given Codex 已由其他入口启动并登录 A
  And 小程序没有启动记录或已保存账号
  When 启动小程序并打开菜单
  Then 显示运行中及 A
  And 自动保存 A，无需点击保存按钮
  And 不退出或重启 Codex，不改写活动 auth.json

Scenario: 识别外部登录与凭据刷新
  Given 小程序正在运行
  When 用户在 Codex 中登录或认证文件刷新
  Then 自动刷新账号显示并保存最新有效凭据

Scenario: 添加账号使用原 App 登录
  Given A 正在运行
  When 点击添加账号
  Then 退出 Codex，保存 A，移除活动 auth.json 并重启原 App
  And 用户直接在原 App 中登录 B 后自动保存 B
  And 继续使用原配置、项目、会话与数据库

Scenario: 放弃添加后切回原账号
  Given 添加账号时尚未完成登录
  When 用户选择已保存的 A
  Then 退出 Codex，恢复 A 的凭据并重启

Scenario: 切换失败不丢失已保存凭据
  Given A 与 B 已自动保存
  When 退出、保存、写入或启动某一步失败
  Then 报告失败，账号快照保留，菜单允许重试
  And 未退出或当前凭据未保存时不移除或替换活动认证

Scenario: 从设置删除已保存账号
  Given 设置窗口列出已保存的 A 与 B
  When 用户删除 B 并确认
  Then B 从保存列表与切换菜单移除
  And 活动认证、Codex 运行状态和会话保持不变
  When 用户取消删除确认
  Then 账号记录保持不变

Scenario: 删除当前账号不会立即自动保存回来
  Given A 是当前账号且已自动保存
  When 用户确认删除 A 的保存记录
  Then 菜单仍显示当前账号 A，已保存列表不包含 A
  And 后续刷新、凭据刷新和小程序重启不重新保存当前 A
  When 用户通过添加账号重新登录 A
  Then A 再次自动保存

Scenario: 外部启动退出与小程序退出
  When Codex 在外部启动或退出
  Then 菜单更新运行状态
  When 退出小程序
  Then 正在运行的 Codex 继续运行
```

开发测试使用虚构凭据与测试目录，不切换真实账号、不退出当前聊天。实现后做独立审阅和针对性测试；真实验收先验证接管已运行 App 与自动保存，再在用户准备好退出 App 时验证添加、切换和原会话继续。

## 实现边界

不 fork codex-profiles，不采用两个图标方案。使用原安装 App 的常规退出和启动能力，菜单图标使用系统符号。手动切换账号，不自动按额度轮换。

本设计及下方两张 UI 原型已由用户批准。应用最终名称为 CodeXwitch，中文说明为“Codex 账号切换器”；原型图中的 Codex Accounts 在实现中替换为 CodeXwitch。产品代码尚未开始。
